1.2 后台入口与配置（官方）

  1. 启用：管理后台 → 应用管理 → 微信客服。【确定】https://open.work.weixin.qq.com/help2/pc/17961
  2. 开 API：管理后台 → 应用管理 → 微信客服 → 点「API」→「可调用接口的应用」选自建应用。【确定】https://developer.work.weixin.qq.com/document/path/94638
  3. 指定账号：「通过API管理微信客服账号 → 企业内部开发」选中要交给 API 的客服账号。设置后，该账号的消息和事件都回调给企业，官方原生接待规则暂不生效。【确定】94638
  4. 接待人员必须在应用可见范围内，否则报 60030。【确定】94638
  5. 拿客服链接：后台「获取客服链接」，或调接口 kf/add_contact_way（可带场景参数，用来区分客户从哪里来）。https://developer.work.weixin.qq.com/document/path/94665 （第三方版 96416）
  6. 回调 URL / Token / EncodingAESKey 配在 API 设置里。域名要过主体校验，境外 .co.kr 走 21611 申诉（见 1.3）。

1.3 境外主体能不能用

  • kf 能用【确定】：境外认证后「微信客服接待客户数最高无上限、账号数最高 5000」；未认证「100 人 / 10 个账号」。https://open.work.weixin.qq.com/help2/pc/20476 （对比图 raw/os/img20476.png）。17961 原文："企业未认证时，累计可接待100位客户；已验证未过期企业，每天可接待100位客户；企业已认证时，每天可接待的客户数无上限。"
  • 回调域名【待核实】：域名备案主体要和企业主体相同或有关联（https://open.work.weixin.qq.com/wwopen/common/readDocument/40754 ）。按 21611：
  • 已认证/已验证的企业，可以申请配置和自己主体一致的域名，被拦截时走「可信域名验证申诉」；没有 ICP 备案的境外域名，要提供申请主体的域名购买记录（拿不出来就用写有域名的发票或合同）。
  • 未认证/未验证的企业可以直接配，但被拦截时不能申诉。
  • 来源：https://open.work.weixin.qq.com/help2/pc/21611
  • KB 记录：api.lesihi.co.kr 已过可信域名验证。service.lesihi.co.kr 过没过，未知。
  • 注意：2023-12-01 起，新企业不能再用系统应用凭据 调 kf 接口（存量企业不受影响）。https://developer.work.weixin.qq.com/document/path/94677 。「转人工」助手说自建应用还没建，那 ally 现在用的是哪个凭据，要在源码包里确认【待核实】。

1.4 同一个客服账号能不能同时交给 ally 和 TCCC（已查官方）

  • 官方原文："一个客服账号同一时间只能由一方开发者来通过API管理会话消息"，以及"一个客服账号同一时间，只能授权给一个第三方来管理"。【确定】https://developer.work.weixin.qq.com/document/path/96368
  • 腾讯云 TCCC 文档：如果企业微信后台在管理微信客服，TCCC 管理会话服务流时会报错，"此时需要关闭企业微信管理微信客服的功能"。【确定（厂商文档）】https://cloud.tencent.com/document/product/679/88892
  • 结论：一个客服账号接 ally，就不能同时接 TCCC。要试 TCCC，只能另开一个测试客服账号授权给它，并且要先弄清楚"关闭企业微信管理"会不会影响员工在企业微信里接待（【推测】会影响）。

1.5 限制（官方）

  • 客户主动发消息后，48 小时内最多发 5 条。机器人、API 发的消息和满意度评价都算在内。客户再发消息就重新计。【确定】17961、94677
  • 只有会话状态是 0（新接入待处理）或 1（智能助手接待）时 API 才能发；状态 3（人工接待）时调用会报 95018。【确定】https://developer.work.weixin.qq.com/document/path/94669 ；错误码 95001 / 95002 见 90313。
  • sync_msg 只能取近 3 天，读不到自己 send_msg 发的消息。【确定】https://developer.work.weixin.qq.com/document/path/94670
  • send_msg_on_event：非工作时间提示、排队提示的 code 48 小时有效，欢迎语的 code 20 秒有效。【确定】https://developer.work.weixin.qq.com/document/path/95122 。这类事件消息算不算进 5 条额度：【查不到】，要实测。
  • 交给 API 后，后台原生的「接待时间 / 非接待时间自动回复」不生效（94638）。所以 kf 里的下班回复必须由 ally 发。
  • 只能一对一，进不了群（知识笔记 §2.5）。

3.3 限制（官方 21273）

  • 触发时间按东八区："触发时间是东八区的时间"。下班时间只能选 17:00 以后，上班时间只能选 10:00 以前（都是北京时间）。换成首尔时间（UTC+9）就是：最早 18:00 下班、最晚 11:00 上班。例：想让首尔 19:00 到次日 09:00 生效，就填北京时间 18:00 到次日 08:00。
  • 工作日最少选 5 天。法定节假日不影响触发；调休补班日不会自动算工作日。
  • 只对「客户身份」的单聊触发，群聊不触发。
  • 每个下班时段只回一次：下班后客户发的第一条消息触发，之后不再回，直到下一个下班时段。员工在下班期间回过客户，这个时段就不再触发。
  • 语音通话 / VoIP 不触发；语音消息会触发；员工账号状态异常也会触发。

4. 三条路线怎么配合（总流程）
